## Issues Fixed

### ✅ 1. Profile Picture Upload (400 Error)

**Error:**
```
POST https://freshmanna-api.ailabsafrica.com/api/v1/media/upload-image 400 (Bad Request)
Avatar upload error: {message: 'Request failed with status code 400'...}
```

**Root Cause:**
The issue was with manually setting the `Content-Type: multipart/form-data` header when uploading files with axios. When you manually set this header, you don't include the required `boundary` parameter that separates different parts of the multipart form data.

**The Problem:**
```typescript
// ❌ WRONG - Missing boundary parameter
const response = await apiClient.client.post("/media/upload-image", formData, {
  headers: {
    "Content-Type": "multipart/form-data",  // Missing boundary!
  },
});
```

When sending multipart/form-data, the Content-Type header needs to look like:
```
Content-Type: multipart/form-data; boundary=----WebKitFormBoundary7MA4YWxkTrZu0gW
```

The boundary is automatically generated by the browser/axios and used to separate the different fields in the form data.

**The Solution:**
```typescript
// ✅ CORRECT - Let axios set Content-Type with boundary
const formData = new FormData();
formData.append("file", file);
formData.append("category", "avatars");

const response = await apiClient.client.post("/media/upload-image", formData);
// Axios automatically sets: Content-Type: multipart/form-data; boundary=...
```

## Technical Explanation

### Why Manual Content-Type Breaks Multipart Forms

1. **Multipart Form Data Structure:**
   - Each field is separated by a boundary string
   - The boundary is random and unique for each request
   - The server uses the boundary to parse the form fields

2. **What Axios Does Automatically:**
   - Detects FormData object
   - Generates unique boundary
   - Sets header: `multipart/form-data; boundary=----XYZ123`
   - Properly formats the request body with boundaries

3. **What Happens When You Set It Manually:**
   - You only set `multipart/form-data`
   - Missing boundary parameter
   - Server can't parse the request
   - Returns 400 Bad Request

### Example of Proper Multipart Request

```http
POST /api/v1/media/upload-image HTTP/1.1
Content-Type: multipart/form-data; boundary=----WebKitFormBoundary7MA4YWxkTrZu0gW

------WebKitFormBoundary7MA4YWxkTrZu0gW
Content-Disposition: form-data; name="file"; filename="avatar.jpg"
Content-Type: image/jpeg

[binary image data]
------WebKitFormBoundary7MA4YWxkTrZu0gW
Content-Disposition: form-data; name="category"

avatars
------WebKitFormBoundary7MA4YWxkTrZu0gW--
```

## Today's Devotional 404 - Not a Bug

### Error Seen:
```
GET https://freshmanna-api.ailabsafrica.com/api/v1/devotionals/today 404 (Not Found)
```

### Explanation:
This is **NOT a bug** - it's expected behavior when there's no devotional scheduled for today.

**Backend Behavior:**
- Endpoint: `GET /api/v1/devotionals/today`
- Returns 404 if no devotional is published for today
- Error message: `"No devotional scheduled for today ({date})"`

**Frontend Handling:**
The Today.tsx page already handles this gracefully:

```typescript
const { data: devotional, isLoading, error } = useQuery({
  queryKey: ['today-devotional'],
  queryFn: async () => {
    const response = await apiClient.getTodaysDevotional();
    return response as TodaysDevotional;
  },
  retry: (failureCount, error: any) => {
    // Don't retry on 404 - no devotional for today is expected
    if (error?.response?.status === 404) {
      return false;
    }
    return failureCount < 2;
  },
});

// Shows user-friendly message when no devotional
if (error || !devotional) {
  return (
    <div className="text-center">
      <Calendar className="w-16 h-16 mb-4" />
      <h2>No Devotional Today</h2>
      <p>There's no devotional scheduled for today. Check back tomorrow!</p>
      <Button onClick={() => navigate('/feed')}>
        Browse All Devotionals
      </Button>
    </div>
  );
}
```

**Why This Happens:**
- Devotionals are manually published by admins/pastors
- Not every day has a devotional scheduled
- The app gracefully handles this with a nice empty state
- Users can still browse other devotionals

**No Action Needed** - This is working as designed.

## Key Learnings

### When Working with FormData in Axios:

**DO:**
- ✅ Let axios handle Content-Type automatically
- ✅ Just pass FormData directly
- ✅ Axios will set the boundary

**DON'T:**
- ❌ Set Content-Type manually for FormData
- ❌ Try to set the boundary yourself
- ❌ Override axios's automatic handling

### Code Pattern to Follow:

```typescript
// Profile picture upload
const formData = new FormData();
formData.append("file", file);
formData.append("category", "avatars");

// Just post - no headers needed
const response = await apiClient.client.post("/media/upload-image", formData);
```

## Related Documentation

### Backend API Endpoint

**Endpoint:** `POST /api/v1/media/upload-image`

**Authentication:** Required (Bearer token)

**Form Fields:**
- `file` (required): Image file to upload
- `category` (optional): Category for organization
  - Options: `avatars`, `devotional-covers`, etc.
  - Default: `devotional-covers`

**Supported Formats:** JPG, PNG, GIF, WebP, HEIC
**Max Size:** 10 MB

**Response:**
```json
{
  "file_id": "uuid",
  "filename": "original-name.jpg",
  "url": "/path/to/file",
  "size": 123456,
  "mime_type": "image/jpeg"
}
```

**Error Responses:**
- 400: Invalid file type or size
- 401: Not authenticated
- 500: Upload failed
