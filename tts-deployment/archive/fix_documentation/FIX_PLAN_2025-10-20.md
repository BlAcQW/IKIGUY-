## **ISSUE #1: MeloTTS Language Validation Bug**

### Problem Description
When attempting to synthesize with MeloTTS, the API returns:
```json
{"detail":"400: Language 'EN' not supported. Available: ['EN', 'ES', 'FR', 'ZH', 'JP', 'KR']"}
```

Even though 'EN' is clearly in the available languages list. The health endpoint shows:
```json
{"status":"healthy","device":"cuda","models_loaded":[]}
```

**Root Cause Hypothesis:**
The API is checking if models are loaded before synthesis, but the error message incorrectly states "language not supported" when it should say "models not loaded yet" or trigger lazy model loading.

### Investigation Steps

1. **Read MeloTTS API implementation**
   - File: `/opt/kasaai/apps/tts-deployment/docker/melotts/app.py`
   - Look for language validation logic
   - Check model loading mechanism

2. **Check MeloTTS logs for more details**
   - Run synthesis request
   - Examine full error traceback
   - Identify exact failure point

3. **Review MeloTTS documentation**
   - Check if models need pre-loading
   - Verify correct API usage

### Solution Options

#### **Option A: Fix Lazy Loading** (Recommended)
- Modify `/synthesize` endpoint to auto-load model on first request
- Cache loaded models for subsequent requests
- Return proper error if model loading fails

**Code Change Location:** `/opt/kasaai/apps/tts-deployment/docker/melotts/app.py`

**Implementation:**
```python
@app.post("/synthesize")
async def synthesize(request: SynthesizeRequest):
    # Check if model is loaded
    if request.language not in loaded_models:
        # Lazy load model
        try:
            load_model(request.language)
        except Exception as e:
            raise HTTPException(
                status_code=500,
                detail=f"Failed to load model for language {request.language}: {str(e)}"
            )

    # Proceed with synthesis
    ...
```

#### **Option B: Pre-load Models on Startup**
- Load all language models when container starts
- Increases startup time but ensures immediate availability
- Higher memory usage (all 6 language models)

**Code Change Location:** `/opt/kasaai/apps/tts-deployment/docker/melotts/app.py`

**Implementation:**
```python
@app.on_event("startup")
async def startup_event():
    logger.info("Pre-loading all MeloTTS models...")
    for lang in SUPPORTED_LANGUAGES:
        try:
            load_model(lang)
            logger.info(f"Loaded model for {lang}")
        except Exception as e:
            logger.error(f"Failed to load {lang}: {e}")
```

#### **Option C: Improve Error Message Only**
- Quick fix: Just make error message clearer
- Doesn't solve lazy loading issue
- Users need to manually trigger model load

**Recommendation:** Use Option A (Lazy Loading) for best user experience.

## **ISSUE #2: OpenVoice PyAV Cython Compilation Error**

### Problem Description

OpenVoice container build fails during PyAV (av) package installation:

```
av/logging.pyx:216:22: Cannot assign type 'const char *(void *) except? 0 nogil'
to 'const char *(*)(void *) noexcept nogil'. Exception values are incompatible.
```

**Root Cause:**
- PyAV's Cython code incompatible with current Python 3.10 + Cython version
- Cython 3.x introduced stricter exception handling requirements
- OpenVoice's `setup.py` tries to build PyAV from source

### Investigation Steps

1. **Check PyAV version requirements**
   - Read OpenVoice repository requirements
   - Check if specific PyAV version needed

2. **Test pre-built wheels**
   - Check if PyAV has pre-built wheels for Python 3.10
   - Try installing from PyPI instead of source

3. **Check Cython version compatibility**
   - Determine which Cython version works with PyAV
   - Test downgrading Cython if needed

### Solution Options

#### **Option A: Use Pre-built PyAV Wheels** (Recommended)
Install PyAV from pre-built binary wheels instead of compiling from source.

**Code Change Location:** `/opt/kasaai/apps/tts-deployment/docker/openvoice/Dockerfile`

**Implementation:**
```dockerfile
# Before installing OpenVoice dependencies
RUN pip3 install --upgrade pip setuptools wheel

# Install PyAV from pre-built wheel BEFORE running pip install -e .
RUN pip3 install av==11.0.0  # Or latest compatible version

# Then install OpenVoice
RUN pip3 install -e .
```

**Pros:**
- Fast build time (no compilation)
- Avoids Cython version conflicts
- Most reliable solution

**Cons:**
- Requires compatible wheel to exist

#### **Option B: Pin Cython Version**
Install older Cython version compatible with PyAV.

**Code Change Location:** `/opt/kasaai/apps/tts-deployment/docker/openvoice/Dockerfile`

**Implementation:**
```dockerfile
# Install specific Cython version before PyAV
RUN pip3 install "Cython<3.0"

# Then proceed with OpenVoice installation
RUN pip3 install -e .
```

**Pros:**
- Maintains source build approach
- Works if no pre-built wheels available

**Cons:**
- Longer build time
- May have other compatibility issues

#### **Option C: Remove PyAV Dependency**
Replace PyAV with alternative audio library (pydub, soundfile).

**Code Change Locations:**
- `/opt/kasaai/apps/tts-deployment/docker/openvoice/Dockerfile`
- `/opt/kasaai/apps/tts-deployment/docker/openvoice/app.py`

**Implementation:**
```dockerfile
# Remove PyAV, use soundfile instead
RUN pip3 install soundfile librosa
```

```python
# In app.py, replace PyAV usage with soundfile
import soundfile as sf

# Instead of: container = av.open(audio_file)
# Use: data, samplerate = sf.read(audio_file)
```

**Pros:**
- Avoids PyAV entirely
- soundfile is simpler and more reliable

**Cons:**
- Requires code changes
- May need to modify OpenVoice library code
- Higher risk of breaking functionality

#### **Option D: Use Different Base Image**
Switch to base image with pre-installed multimedia libraries.

**Code Change Location:** `/opt/kasaai/apps/tts-deployment/docker/openvoice/Dockerfile`

**Implementation:**
```dockerfile
# Change base image to one with multimedia support
FROM pytorch/pytorch:2.0.1-cuda11.7-cudnn8-runtime

# Rest of Dockerfile...
```

**Pros:**
- Pre-compiled dependencies
- Better multimedia support

**Cons:**
- Different CUDA version may cause issues
- Larger image size

### Recommended Approach

**Two-Phase Strategy:**

**Phase 1: Quick Fix (30 min)**
```dockerfile
# Try pre-built wheel first
RUN pip3 install av --no-build-isolation
```

**Phase 2: Comprehensive Fix (if Phase 1 fails)**
```dockerfile

RUN pip3 install "Cython<3.0" setuptools wheel
RUN apt-get update && apt-get install -y \
    build-essential \
    pkg-config \

    libavcodec-dev \
    libavdevice-dev \
    libavutil-dev \
    libavfilter-dev

# Install PyAV from source with specific version
RUN pip3 install av==10.0.0
```

#### **Option B: Provision New RunPod Instance**

**Steps:**

1. **Create Pod:**
   - GPU: RTX 4090 or A100 (48GB VRAM)
   - Template: PyTorch 2.0 CUDA 11.8
   - Storage: 100GB
   - Expose ports: 8002, 8006, 8008

2. **Setup Instance:**
   ```bash
   # SSH into new instance
   ssh -p <port> root@<host>

   # Install dependencies
   apt-get update
   apt-get install -y git docker.io docker-compose

   # Setup NVIDIA runtime
   distribution=$(. /etc/os-release;echo $ID$VERSION_ID)
   curl -s -L https://nvidia.github.io/nvidia-docker/gpgkey | apt-key add -
   curl -s -L https://nvidia.github.io/nvidia-docker/$distribution/nvidia-docker.list | \
     tee /etc/apt/sources.list.d/nvidia-docker.list
   apt-get update
   apt-get install -y nvidia-container-toolkit
   systemctl restart docker

   # Clone deployment repo
   git clone <repo-url> /opt/tts-deployment
   cd /opt/tts-deployment
   ```

3. **Deploy Services:**
   ```bash
   # Build images
   docker-compose -f docker-compose.runpod.yml build

   # Start services
   docker-compose -f docker-compose.runpod.yml up -d

   # Check status
   docker-compose -f docker-compose.runpod.yml ps
   ```

4. **Configure SSH Tunnels (Local Machine):**
   ```bash
   # Update tunnel script
   vim /opt/kasaai/apps/tts-deployment/scripts/runpod_tunnels.sh

   # Start tunnels
   ./scripts/runpod_tunnels.sh start
   ```

5. **Configure SSL:**
   ```bash
   # On local machine
   sudo certbot --nginx \
     -d f5tts.ailabsafrica.com \
     -d styletts.ailabsafrica.com \
     -d kyutai.ailabsafrica.com \
     --non-interactive --agree-tos --email alfred.anyan@gmail.com --redirect
   ```
